## 0. The problem in one paragraph

185 active listings, 8,514 visits in the last 3 months, 40 orders. Only **15% of visits come from Etsy search** (215 of 1,451 in 30 days).
Half of all traffic lands on 10 listings. 62 listings had fewer than 5 visits in 3 months, 23 had zero.
Root cause, verified listing by listing: **73 listings (39%) carry auto-generated "word salad" tags**
(e.g. `engraved solid women | thin wide edge and | men personalized set | anniversary matching`) that match no buyer query,
and 44 listings have **zero attributes filled**. Titles are metal-first ("14K Yellow Gold Beveled Wedding Band") while
**55% of real search visits contain "mens"/"men's"** and only 4% contain "women". 10k queries outnumber 14k 2:1 and 18k 6:1; white gold leads.
Two listings have Spanish titles on a US shop. Section assignment is inconsistent (53 listings in the wrong section).

## 2. Rules that produce reach (do not relax these)

**Titles**
- Max 140 chars. Primary keyword inside the first 40 characters. Comma-separated phrases, no pipes, no ALL CAPS, no "!!!".
- Wedding bands start with `Mens` (evidence: search-term file). Then karat, metal, style, "Wedding Band".
  Pattern: `Mens 10K White Gold Milgrain Wedding Band, Solid Gold Beaded Edge Comfort Fit Ring for Him and Her, 2-12mm Width, Free Engraving, Made to Order`
- Karat only if the listing actually offers it (check `karats` in the matrix; multi-karat listings use `10K 14K 18K`).
- Christmas and stacking rings: motif first, then `Stacking Ring Solid Gold`, then gift intent (`Christmas Ring Gift for Her`).
- Fidget ring: `Fidget Ring 14K Solid Gold, Anxiety Ring with Moving Bead, ...` (eRank: fidget ring 4.9k searches, KD 3, competition 5.5k — the single best keyword in the shop).
- English only. Spanish titles (4593705293, 4593814704) get rewritten.

**Tags (exactly 13)**
- Each <= 20 chars, lowercase, multi-word buyer phrases, no duplicates, no single adjectives, no fillers ("hi", "to", "and", truncated words).
- Structure per wedding band: 3 head tags (`mens wedding band` always + 2 metal heads) + 1-2 karat tags + 4 style tags + 2 width tags + 2 occasion tags (`anniversary gift him`, `promise ring for him`) + `engraved ring` when personalizable.
- Do not repeat the same 13 tags across the three metal variants of one design: the matrix already varies the metal head tags; keep it that way.
- Never use: brand names (Cartier, Tiffany, Mejuri, Benchmark), "tungsten", "titanium", "silver", "silicone", "plated", "moissanite", "hypoallergenic", "diamond" as a stone (EON sells no stones). "Diamond cut" is a finishing term and stays (owner decision 2026-10-21).

**Attributes** (cannot be set via the scripts; done in the Etsy listing editor by a human, 20 seconds each)
- Every ring: Materials, Gold solidity = Solid gold, Gold purity (10k/14k/18k as offered), Band color, Band width (if single width), Shank type, Style, Occasion = Wedding (bands) or Anniversary, Recipient = Men + Women + Unisex adults, Can be personalized = Yes when engraving is offered.
- 44 listings have zero attributes. Attributes feed Etsy's filters; an empty attribute set is invisible to filtered searches.

**Sections**: use `section_fix` from the matrix (53 moves). Christmas rings stay in "Christmas Spark".

**Never touch**: price, quantity, variations, photos, description, shipping, return policy. Never deactivate or delete a listing. Never create listings.

## 3. The loop (run exactly in this order)

```
cd docs/eon/seo/2026-10-21-etsy-keyword
python3 scripts/generate_matrix.py                  # only after editing rules or panel-variants.json
python3 scripts/apply_matrix.py validate            # must print "0 with rule violations"
python3 scripts/apply_matrix.py plan --top 20       # read every title; it must read like a human wrote it
npm run test:seo-apply                              # (repo root) route decision rules
```

Writes (repo-native, owner decision 2026-10-21): `GET /api/ops/seo-apply?org=EON&ids=<up to 10 ids>&token=<ops token, purpose seo-apply>`
on `https://amuletta.artifactstudio.info`. Dry by default; `&apply=1` writes title, tags and section, re-reads the
listing in the same call, mirrors the panel row and writes an `etsy.seo_push` audit row with before/after (the undo
record). A listing whose live title or tags no longer match the matrix "before" (owner edited it after 2026-10-21)
returns `live-changed` and is not touched. Each call uses one single-use token. The matrix is bundled at build time,
so a regenerated matrix needs a merge and deploy before the route sees it. The Python `apply`/`verify` commands are
kept for reference only.

Batch size: 20 listings per session, priority order. After each batch, STOP and write a 5-line state note to `reports/state-notes.md`
(Done / Decisions / Open / Next action / Context). Then continue only if the owner says go.
Order of batches: (1) the 73 SALAD listings with the most 3-month visits first (traffic at stake), (2) remaining SALAD, (3) zero-visit OK listings, (4) everything else.
If `apply` returns 3 failures on one listing, it is marked failed: do not retry; report the `last_error` to the owner.
If Etsy returns 429, the client backs off automatically. If 401, run `python3 scripts/etsy_client.py auth` again.

Before writing a listing you will see its live title and tags in the dry run. If the live data differs from `data/listings-master.json`
(the owner edited it after 2026-10-21), stop for that listing, mark it `skip`, and tell the owner.
