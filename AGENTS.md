## Cursor Cloud specific instructions

The app is useless without Supabase: every route is auth-gated (`proxy.ts` +
`(dashboard)/layout.tsx`), so to run/test anything you need a local Supabase
stack. Dependencies (`npm install`) are refreshed automatically by the update
script; Supabase + Docker are NOT (they are services, not deps).

### Bring the environment up (run once per fresh VM)

```bash
bash scripts/dev-supabase-setup.sh   # starts Docker + Supabase, provisions DB, writes .env.local, creates test user
npm run dev                          # http://localhost:3000
```

Standard commands (`dev`/`build`/`lint`/`typecheck`) are in `package.json`;
`lint` and `typecheck` pass with no DB. Log in with the seeded test account:

- email: `admin@jadegold.local` · password: `Password123!`
- It owns the seeded `Jade Gold NYC` org, so login lands straight on `/panel`.
  A brand-new user with no org is instead sent to the `/kurulum` setup wizard
  (see `handle_new_user` in migration `0071`).

### Non-obvious provisioning gotchas (why the helper script exists)

- `supabase start` / `supabase db reset` do NOT provision this DB cleanly:
  - Migration `0058_security_hardening.sql` `REVOKE`s execute on
    `public.rebuild_cogs_estimate(uuid, numeric)`, a function that is never
    created anywhere — a fresh apply aborts there. The script applies migrations
    with `ON_ERROR_STOP=0` so this one no-op statement is skipped (harmless).
  - Migrations must be applied as the **`supabase_admin`** superuser
    (`docker exec -U supabase_admin`), NOT `postgres`. The app relies on
    Supabase default privileges to give `anon`/`authenticated` table + function
    access (migrations never `GRANT` table DML themselves); those defaults only
    attach to objects created by `supabase_admin`. Applying as `postgres` yields
    "permission denied for table ..." for logged-in users.
  - Never `DROP SCHEMA public` to reset — that destroys the schema OID the
    Supabase default-privilege grants are bound to, permanently breaking
    `authenticated` grants. To wipe, use `supabase stop --no-backup` then re-run
    the helper script (it starts a bare DB and re-applies).
- Docker here needs `fuse-overlayfs` + `iptables-legacy`; the daemon is started
  manually (the helper script does `sudo dockerd &` and chmods the socket).
- `.env.local` is gitignored and regenerated by the helper from
  `supabase status -o env` (local keys are stable demo defaults).
- Money is stored as integer cents (e.g. form "12,34" -> `1234`); see `lib/money.ts`.
